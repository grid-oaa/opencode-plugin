# OpenCode 提问导航

一个 Chrome MV3 扩展，用于增强 `opencode pair` 的 Web 页面：

- 在聊天窗口右侧显示垂直提问导航，快速定位历史消息；
- 在输入框发送按钮左侧提供优化/撤回图标按钮，优化当前提示词草稿；
- 在优化与发送按钮之间提供跨会话引用入口，选择其他会话的消息插入草稿；
- 在聊天输入框右侧提供悬浮的 AI 对话入口，悬停切换智谱清言 / Kimi / 豆包 / 腾讯元宝，用 Chrome side panel 原样加载网页版，与 OpenCode 上下文隔离；
- 支持收藏提问、添加备注，并把书签或整个会话导出为 Markdown。

## 安装

1. 打开 Chrome，访问 `chrome://extensions/`。
2. 打开右上角「开发者模式」。
3. 点击「加载已解压的扩展程序」，选择本目录。
4. 刷新 `opencode pair` 打开的页面（默认 `http://127.0.0.1:28894`）。

## 使用

- 右侧的横条对应当前会话里的每一条用户提问，上旧下新。
- 未选中项是短浅灰横条，当前项是长黑条；点击热区比横条本身更大。
- 鼠标悬停或键盘聚焦某条 dash：显示一段统一格式的简短摘要；过长内容会省略，不分标题/正文层级。
- 点击 dash：跳转到对应消息；目标消息未渲染时会先取消自动跟随，再按需加载更早的历史并精确定位。
- 跳转需要搜索或加载历史时，会用“正在定位提问…”遮罩隐藏中间的虚拟列表滚动；目标已经渲染时直接对齐，不显示遮罩。
- 滚动聊天时，当前 dash 会跟随高亮；在会话底部时优先高亮最新一条。
- 点击某条提问后会保持选中，直到你再次滚动时间线或使用方向键。
- rail 获得焦点后，可以用 `↑` / `↓` 切换，`Enter` 跳转。

## 提示词优化

在已有会话的输入框中，引用按钮左侧会出现一个与发送按钮同尺寸的优化图标按钮（星形）：

- 点击优化图标：使用当前会话模型（快速模式，不启用 reasoning variant），只把当前草稿发给模型，改写得更清晰、连贯；
- **快速模式不读取完整会话上下文**，因此不会把长会话整段发送给模型，速度更快，但无法解析“这个 / 刚才 / 上面”之类的指代；
- 优化结果只回填到输入框，不会自动发送，也不会写入会话历史，因此不会影响后续上下文；
- 优化请求在后台继续：切换到其他 OpenCode tab 不会中断，切回后会自动应用结果；如果草稿已变化则丢弃；
- 不同会话的优化互不影响，可以同时进行；
- 优化成功后图标变为撤回（undo）图标，点击可恢复优化前的原文；
- `@文件` / `@agent` 等引用会以占位符交给模型，并在回填时恢复为原始引用，不会被改写或丢失；
- 截图、上传文件等附件保持不变；优化只基于文字，不会读取附件内容；
- 请求中图标变为旋转加载指示器；失败时按钮出现红色警示描边，悬停可查看原因，原文不变；
- 输入框为空、只有斜杠命令或尚未进入已有会话时，按钮不可用。

## 引用其他会话

- 点击输入框中「优化」和「发送」之间的链接图标，打开会话选择器；
- 默认查看当前项目的其他会话，可通过项目名称切换到其他项目；项目按 OpenCode 记录的活跃时间倒序排列，缺少时间的项目排在末尾；搜索可跨项目匹配项目名称、路径和会话标题；
- 选择会话后预览并勾选一条或多条助手回答，点击「插入引用」后，完整文本会追加到草稿，不会自动发送；
- 引用是插入时的文本快照，不包含助手推理、工具输出或附件内容；长内容会提示可能消耗大量 Token；
- 会话和消息各最多读取 5000 条，达到上限时会显示提示；当前项目以 OpenCode 的项目 ID 判断，包含同项目的不同 worktree；
- 引用内容通过当前服务器同源接口读取，切换项目范围不会访问其他服务器。

## AI 对话侧栏

聊天输入框右侧有一个悬浮的聊天气泡图标：

- 鼠标移入图标，会向上展开已支持的 AI 站点 logo 菜单；鼠标移开自动收起；
- 点击某个 logo：切换到该 AI 并打开 Chrome 原生 side panel；
- 点击主图标：只展开/聚焦站点菜单，不会直接打开侧栏；只有点击 logo 才会打开；
- 图标默认半透明，鼠标移入或键盘聚焦后变清晰；菜单支持方向键、Enter、Escape；
- 按钮底部与输入框底边对齐，并跟随输入框高度和窗口宽度；空间不足时自动移到输入框右上角内侧；
- 不占用 Composer 操作栏，原来的“优化 + 发送”布局不变。

当前菜单里有四个站点：

- 智谱清言：`https://chatglm.cn/`
- Kimi：`https://www.kimi.com/`
- 豆包：`https://www.doubao.com/chat/`
- 腾讯元宝：`https://yuanbao.tencent.com/`

其中智谱清言和 Kimi 已验证可正常使用；豆包、腾讯元宝可以加载页面，但登录流程和侧栏宽度还需要实际测试。

侧栏行为：

- 侧栏直接加载目标站点，不经过扩展代理，也不读取或修改聊天内容；
- 同一个 side panel 只保留一个 iframe；切换站点会重新加载目标站点，不会同时驻留多个 AI 页面；
- 侧栏顶部 30px 工具条显示当前站点名称，并提供刷新和在标签页打开；
- 上次选择的站点保存在本地，侧栏和菜单选中状态会记住它；主图标只负责展开菜单，不会直接打开侧栏；
- side panel 宽度可以用鼠标拖动调整；页面变窄后 OpenCode 聊天区会自动重新居中；
- 智谱清言按桌面布局渲染；侧栏很窄（约 400px）时右侧可能被裁切，建议拖宽到约 800px，或点击智谱清言左上角的收起侧栏按钮；
- Kimi 在约 380px 侧栏下可以渲染，但登录态和实际聊天仍需验证；
- 豆包、腾讯元宝的侧栏宽度和登录流程尚未验证；如果页面被裁切，请拖宽 side panel；
- 如果侧栏一直空白，优先尝试“在标签页打开”，或在 Chrome 站点设置中允许对应站点使用第三方 Cookie；
- 也可以通过 Chrome 工具栏的扩展图标打开同一个侧栏，加载上次选择的站点。

## 全局书签、备注与导出

悬停右侧提问，预览卡底部有「收藏 / 备注 / 跳转」：

- 收藏：rail 条目左侧出现星标；
- 备注：保存后自动收藏该提问；备注只存在本地；
- 跳转：使用原有的提问定位逻辑。

聊天输入框右侧、对话图标右边有一个同尺寸的书签按钮；首页右下角也有一个固定书签入口。也可以按 `Alt+B` 打开“全局书签”抽屉：

- 显示所有会话的书签，按会话分组，标题显示书签数和会话数；
- 每个会话分组默认全部折叠，支持单独展开/收起；搜索或筛选到某个会话时会自动展开；
- 支持按提问、备注或会话标题搜索，也可以只筛选某个会话；
- 点击当前会话的书签会跳转；点击其他会话的书签会打开对应会话并定位到该提问；
- 支持编辑备注、取消收藏；取消收藏会同时删除备注；
- 点击书签旁的「插入」，可将对应回答追加到当前会话输入框，不包含提问或备注，也不会自动发送；其他服务器的书签无法直接读取回答；
- 点击「复制」可将对应回答复制到剪贴板，不修改当前草稿；
- 每条书签前有复选框，支持勾选多条，也可以全选当前筛选结果；
- 底部「导出选中」「全部书签」「导出会话」会直接下载 Markdown。

导出说明：

- 书签导出是全局的，按会话分节，包含提问、对应助手回答和备注；
- 「导出选中」只包含勾选的书签；
- 「全部书签」包含所有会话的书签；
- 其他会话会按需读取消息；读取失败或跨 server 时只导出提问和备注；
- 「导出会话」仍然只导出当前会话的完整 Q&A；
- 默认不包含 reasoning；工具调用按轮次汇总成名称和次数，避免导出几千行工具日志；
- 附件只输出文件名，不内嵌附件内容；
- 超长会话最多拉取 25 页消息，可能只导出前 5000 条。

书签保存在 `chrome.storage.local` 的 `ocBookmarksV1` 中，按 `server + sessionID + messageID` 区分。“全局”指跨会话管理，不跨设备同步；清除扩展数据会丢失。

## 实现方式

- 通过同源 `GET /api/session/{sessionID}/message?type=user&order=asc` 获取用户提问，按 `cursor` 翻页（单页上限 200）。
- 跳转不依赖 OpenCode 的 hash 处理：先派发向上滚轮取消自动跟随，再按需贴顶触发历史加载，通过虚拟列表的 `data-message-id` 行定位目标，并按滚动容器和 sticky 标题高度精确对齐；hash 只在跳转成功后同步，避免 Router 反向接管滚动。
- 会话压缩前的提问在时间线中没有原始 user 消息行时，会定位到压缩摘要并给出提示。
- 使用 Shadow DOM 注入 UI，颜色继承 `--v2-*` 主题变量，不修改 OpenCode 源码。
- 新提问通过 `MutationObserver` + 10 秒尾部轮询增量刷新。
- 提示词优化使用快速模式：`POST /api/experimental/generate/text`，只发送草稿和当前会话模型，不读取完整会话上下文，也不写入历史。
- 模型 ref 使用当前会话模型 id/providerID，但不带 reasoning variant，以缩短响应时间。
- `@` 引用使用占位符交给模型；返回后校验占位符，并用原始 mention DOM 节点重建编辑器，保留引用信息。
- 编辑器更新通过 selection + `input` 事件同步到 OpenCode 的 prompt 状态。
- 优化耗时会在页面控制台通过 `[OC Prompt Nav] 提示词优化完成 { elapsedMs }` 输出。

## 限制

- 只注入 `http://127.0.0.1/*` 和 `http://localhost/*`，并且只对 OpenCode Web 页面生效；HTTPS 或自定义域名需要自行补充 `manifest.json` 的 `matches`。
- 适配 OpenCode v2.2.0 的 Web UI；如果后续版本调整了 API 或 `#message-` 深链行为，可能需要同步更新 `content.js`。
- 默认按单 server 处理；多 server 或远程隧道场景需要额外解析目标 server 的 API 地址。
- 会话进行中执行 revert 后，导航可能暂时保留被撤销的条目；刷新页面即可恢复（当前只在加载会话时按 `revert.messageID` 过滤）。
- 提示词优化只支持已有会话，不支持 `/new-session` 草稿；斜杠命令不优化。
- 优化只基于文字，不读取当前草稿的截图/附件内容；附件本身不会被修改。
- 快速模式不读取会话上下文，无法解析“这个 / 刚才 / 上面”等指代；需要上下文时后续可增加轻上下文模式。
- 使用 `experimental` 无状态生成接口；接口或模型变化时可能失败。
- 使用当前会话模型但不带 reasoning variant；模型超时或不支持时会失败，原文保持不变。
- AI 对话侧栏需要 Chrome 116+；Edge 或其他 Chromium 浏览器是否支持 `sidePanel` 需要单独验证。
- 当前菜单包含智谱清言、Kimi、豆包、腾讯元宝；智谱清言和 Kimi 已验证可正常使用，豆包和元宝的登录态与真实聊天仍需实测。
- DeepSeek 使用 `frame-ancestors 'none'`，通义千问使用 `X-Frame-Options` + 阿里域名白名单，Z.ai 使用 `X-Frame-Options: SAMEORIGIN`，目前无法嵌入。
- 豆包的 CSP 目前是 report-only，并白名单了部分扩展 ID；当前可以加载，但未来策略收紧时可能失效。腾讯元宝的 QQ/微信登录可能依赖弹窗，需要实测。
- AI 站点登录依赖各自 Cookie；如果 Chrome 阻止第三方 Cookie，可能在侧栏内无法保持登录，此时请用“在标签页打开”。
- AI 站点目前允许 iframe 加载；如果以后增加 `X-Frame-Options` 或 `frame-ancestors` 限制，侧栏会显示回退入口。
- side panel 是浏览器级侧栏，打开后会占用页面宽度，OpenCode 聊天区会按响应式布局重新居中。
- 智谱清言的桌面布局需要较宽侧栏；约 400px 时右侧聊天区可能被裁切，建议拖到约 800px，或收起智谱清言自己的左侧栏。Kimi 的窄侧栏布局可用，但登录/聊天仍需确认；豆包和腾讯元宝的布局宽度需要实测。
- 悬浮菜单按桌面鼠标悬停设计；触摸设备暂未适配。
- 嵌入第三方 AI 网页版可能受各自服务条款约束；发布前请自行确认，logo 也需确认品牌使用许可。
- 全局书签按会话分组管理，但只保存在当前浏览器 profile，不跨设备同步；跨 server 的书签只能导出提问和备注。
- 取消收藏会同时删除备注，目前没有撤销。
- Markdown 导出不包含 reasoning 和附件内容，只保留附件名；超长会话最多导出前 5000 条消息。
- 导出依赖浏览器下载；如果浏览器禁止自动下载，需要在下载设置中放行。
- 优化任务按 sessionID 保存；切换 tab 只切换按钮绑定，不会 abort 请求；浏览器 tab 关闭时通过 `pagehide` 统一清理。
- 提问导航只读取本机会话接口；提示词优化会把草稿发送给当前会话配置的模型提供方（与正常发送消息一致），不会上传到其他服务。
- AI 对话侧栏使用 `chrome.sidePanel` + 扩展页面 iframe，由 `background.js` 打开全局侧栏并保存 OpenCode 主题变量。
- 站点配置集中在 `ai-sites.js`，包含名称、URL 和内嵌 data URL logo；logo 不用扩展资源 URL，避免 opencode 页面的 CSP 拦截。
- 菜单选择站点后写入 `chrome.storage.local` 的 `ocAiSite`；侧栏监听变化并切换 iframe，顶部标题和“在标签页打开”会跟随当前站点。
- 侧栏 iframe 加载的是原站页面；扩展没有申请这些 AI 站点的 host 权限，因此无法读取或修改其中的聊天内容。
- 悬浮入口由 Shadow DOM 注入，使用 `--v2-*` 主题变量；按钮底部与当前 Composer 底边对齐，并用 `ResizeObserver` 跟随输入框高度变化；不占用 Composer 操作栏。
- 悬浮菜单向上展开，默认对齐按钮右侧；与右侧提问导航重叠时会自动向左避让；支持鼠标悬停、键盘方向键和 Escape。
- 侧栏顶部是 30px 的扩展自有工具条，只放刷新和在标签页打开；iframe 从其下方开始，避免覆盖站点自己的顶部控件。
- 书签/备注保存在 `chrome.storage.local` 的 `ocBookmarksV1`，按 server、sessionID、messageID 生成 key，并记录 sessionTitle、sessionPath；多窗口通过 `storage.onChanged` 同步。
- 预览卡、全局书签抽屉和备注弹层都使用 Shadow DOM + `--v2-*` 主题变量；`Alt+B` 打开全局书签抽屉。
- 书签勾选状态由抽屉内 checkbox 维护，按 server+sessionID+messageID 保存；切换会话时清空；导出选中项时按会话分组读取对应 Q&A 轮次。
- 全局导出通过同源消息 API 分页读取每个会话的全部消息，按用户提问聚合成轮次，生成 Markdown 后用 Blob 下载；读取失败时回退到提问和备注；reasoning 跳过，工具调用按轮次汇总。

## 文件

```text
manifest.json   # Chrome MV3 配置
ai-sites.js     # AI 站点配置：名称、URL、内嵌 logo
background.js   # 侧栏打开、工具栏图标行为、站点和主题存储
sidepanel.html  # AI 对话侧栏页面
sidepanel.css   # 侧栏加载态、顶部工具条和回退卡片样式
sidepanel.js    # 侧栏 iframe 加载、站点切换、刷新、在标签页打开、主题同步
content.js      # 会话导航 + 提示词优化 + AI 入口 + 书签/备注/导出
README.md
```
